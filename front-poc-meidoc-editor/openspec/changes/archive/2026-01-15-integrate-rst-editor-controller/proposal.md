# RST統合とデバッグビュー

## Why

現在、CodeMirror と ProseMirror は独立して動いており、相互運用性が低く、構造の堅牢性が欠けています。RST を導入することで以下を実現します：

1.  **堅牢な構造保持**: RST により、不正な XML も可能な限り構造として維持する。
2.  **完全な同期**: 一方のエディタでのカーソル位置や変更を、もう一方へ正確に反映する。
3.  **編集の安全性**: 同期ラグによる競合を防ぐためのロック機構を導入する。

## What Changes

1.  **`EditorController` の中心化**:
    - RST を唯一の状態として管理。
    - **排他制御**: 片方のエディタが編集中（および同期処理中）は、もう片方の入力をブロックする状態管理を行う。
    - **ログ記録**: 編集命令の受信と適用アクションを詳細に記録し、デバッグビューで閲覧可能にする。

2.  **厳格なマッピング戦略**:
    - PM -> RST の変換において、全再シリアライズではなく、ProseMirror の Step/Transaction を RST の編集操作へ正確にマッピングすることを試みる。

3.  **MEI 要素の表示**:
    - `<mei>` 要素以下は、ProseMirror 上でスキーマ定義により `atom` ノードとして扱い、スクロール可能な `<pre>` タグ内に生の XML テキストを表示する。
